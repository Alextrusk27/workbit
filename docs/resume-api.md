# Resume API: `/api/v1/resumes`

Резюме пользователя: сервис принимает исходный файл резюме, сохраняет его на сервере и отдаёт
список загруженного. Сейчас реализована только загрузка и список. Принимаются три формата: PDF,
DOCX и TXT. Содержимое файла не читается и не разбирается: сервис определяет формат по первым
байтам и запоминает файл как есть. Загрузка бесплатна, лимиты баланса не списываются.

Ответы и тела ошибок приходят в JSON, а запрос на загрузку отправляется как multipart.

## Аутентификация

Оба эндпоинта защищены так же, как остальные закрытые ручки: cookie `access_token`
(см. `docs/auth-api.md`), в браузере запросы идут с `credentials: 'include'`. Резюме всегда
принадлежит пользователю из токена, чужие резюме через API не видны.

## Эндпоинты

| Метод | Путь | Назначение | Авторизация |
|---|---|---|---|
| GET | `/api/v1/resumes` | список своих резюме, новые сверху | cookie `access_token` |
| POST | `/api/v1/resumes` | загрузка файла резюме | cookie `access_token` |

## Запросы

`POST /api/v1/resumes` принимает `multipart/form-data` с одним полем:

| Поле | Тип | Описание |
|---|---|---|
| `file` | файл | исходный файл резюме |

`Content-Type` вручную не ставят: границу (`boundary`) проставляет браузер, когда в `fetch`
передают `FormData`. Фронт так и делает: `formData.append('file', file)`.

Размер ограничен настройками multipart в `application.yml`: файл не больше 5 МБ, весь запрос не
больше 6 МБ. У `GET` нет ни тела, ни параметров.

## Ответы

Оба эндпоинта возвращают резюме в одной форме:

```java
record ResumeResponse(UUID id, String name, Resume.Format format, String originalFilename, int sizeBytes, Instant uploadedAt)
```

| Поле | Описание |
|---|---|
| `id` | идентификатор резюме |
| `name` | название резюме, по которому его различает пользователь, берётся из имени файла |
| `format` | формат исходного файла: `PDF`, `DOCX` или `TXT` |
| `originalFilename` | имя файла, как оно пришло при загрузке (без пути, не длиннее 255 символов) |
| `sizeBytes` | размер файла в байтах |
| `uploadedAt` | момент загрузки, ISO-8601 в UTC |

Значения `format` берутся из enum `Resume.Format`: `PDF`, `DOCX`, `TXT`. Все три доступны при
загрузке, формат выбирает сервис по содержимому файла (см. «Поведение»).

- `GET /api/v1/resumes`: `200` и массив `ResumeResponse`, от новых к старым по моменту загрузки.
  Если резюме нет, массив пустой. Пагинации нет, отдаётся всё.
- `POST /api/v1/resumes`: `201`, заголовок `Location: /api/v1/resumes/{id}` и `ResumeResponse`
  нового резюме в теле. Эндпоинта `GET /api/v1/resumes/{id}`, на который указывает `Location`,
  пока нет, переходить по этому адресу не нужно: все данные уже в теле ответа.

## Поведение

- **Формат определяется по первым байтам.** Заголовок `Content-Type` части `file` не
  учитывается. Проверки идут по порядку, срабатывает первая подходящая:
  1. Если в первых 1024 байтах встречается `%PDF-`, это `PDF`.
  2. Если файл начинается с ZIP-сигнатуры (`PK\x03\x04`), это `DOCX`, но только когда имя файла
     заканчивается на `.docx` (регистр не важен). Любой другой ZIP получает `422` с деталью
     `Unsupported format`. Архив при этом не открывается, поэтому переименованный в `.docx`
     xlsx или другой ZIP-файл сохранится как `DOCX`.
  3. Если файл начинается с сигнатуры OLE2 (старый `.doc`, а также DOCX под паролем) или RTF
     (`{\rtf`), ответ `422` с деталью `Legacy format`.
  4. Остальное пробуется как текст и при успехе получает `TXT`. Файл декодируется как строгий
     UTF-8 (BOM допускается), а если не получилось, как Windows-1251. Кодировка нигде не
     хранится. Файл не считается текстом, если в нём есть байт `NUL` или больше 1% управляющих
     символов (табуляция, перевод строки, возврат каретки и form feed не в счёт). Тогда ответ
     `422` с деталью `Unsupported format`.
  5. Пустой файл получает `422` с деталью `Unsupported format`.

  Расширение имени учитывается только на втором шаге, чтобы отличить DOCX от прочего ZIP. На
  выбор формата в остальных случаях оно не влияет: файл `cv.docx` с PDF внутри сохранится как
  `PDF`, а `cv.pdf` с обычным текстом как `TXT`. Текстовый файл со строкой `%PDF-` в первых
  1024 байтах тоже будет принят как `PDF`.
- **Содержимое не проверяется и не извлекается.** Сигнатура ещё не гарантирует, что файл целый и
  открывается. Сервис не читает текст резюме, не проверяет, что это действительно резюме, а не
  другой документ, и не ищет в нём вредоносное содержимое.
- **Название берётся из имени файла.** Сначала из имени отбрасывается путь (всё до последнего `/`
  или `\`; некоторые клиенты присылают полный путь) и крайние пробелы. Затем от результата
  отрезается одно расширение `.pdf`, `.docx` или `.txt` (регистр не важен), а серия пробелов
  внутри сжимается до одного. Остальные точки остаются в названии, как и любые другие
  расширения: `Иванов Java.pdf` даёт название `Иванов Java`, `v2.1 резюме` остаётся
  `v2.1 резюме`, а `cv.final` остаётся `cv.final`. Название обрезается до 100 символов. Если
  после этих шагов оно пустое (имя не пришло вовсе или состоит из одного расширения, например
  `.pdf`), название равно `Резюме`. Название не уникально: два файла с одним именем дают два
  резюме с одним названием.
- **Имя файла.** В `originalFilename` лежит то же имя без пути и крайних пробелов, обрезанное до
  255 символов. Если имя пустое или не пришло вовсе, подставляется `resume.<расширение>` по
  определённому формату: `resume.pdf`, `resume.docx` или `resume.txt`. Изменить название или
  имя после загрузки пока нельзя: эндпоинтов изменения нет.
- **Файл хранится на диске сервера.** В базе лежат только метаданные из `ResumeResponse`, сам
  файл записывается в каталог `RESUME_STORAGE_DIR` (по умолчанию `data/resumes`) по пути
  `{идентификатор пользователя}/{идентификатор резюме}`, без расширения. Запись идёт через
  временный файл с атомарным переименованием, поэтому недописанный файл под итоговым именем не
  появляется. Если после записи файла не удалось сохранить строку в базе, файл удаляется.
  Скачивания файла через API пока нет.
- **Число резюме не ограничено.** В коде нет проверки на максимальное количество резюме у одного
  пользователя, повторная загрузка того же файла создаёт новое резюме.
- **Лимиты не списываются.** Загрузка не платная операция, баланс не проверяется и не меняется,
  `402` у этих эндпоинтов не бывает.

## Клиент на фронте

Клиент лежит в `frontend/src/features/resume/`, страница списка в `frontend/src/pages/resume/`.

- `resumeApi.list()` и `resumeApi.upload(file)` зовут `GET` и `POST` через общий `apiFetch`, с
  теми же cookie и обновлением токена по `401`, что и остальные ручки.
- Поле выбора файла в интерфейсе ограничено `accept=".pdf,.docx,.txt"`. Это подсказка
  браузеру, не защита: решает бэк.
- До отправки страница проверяет расширение выбранного файла (`files.ts`, регистр не важен). Если
  оно не `.pdf`, `.docx` и не `.txt`, пользователь видит «Поддерживаются только PDF, DOCX и TXT.»,
  и запрос не уходит. Из-за этого файл с расширением `.doc` или `.rtf` до бэка не доходит, а
  `Legacy format` приходит, когда старый документ Word переименован в разрешённое расширение
  или DOCX защищён паролем.
- После успешной загрузки хук `useUploadResume` отправляет цель Метрики `resume_upload` и
  инвалидирует кэш списка (`['resumes']`), так что список перечитывается заново.
- Детали из `ApiError.errors[0]` переводятся в `errors.ts`: `Unsupported format` показывается как
  «Поддерживаются только PDF, DOCX и TXT.», а `Legacy format` как «Старые файлы Word, RTF и
  документы Word под паролем не поддерживаются. Сохрани файл как DOCX без пароля или PDF.».
  Остальные ошибки идут через общий `getErrorMessage`.

## Ошибки

Тело ошибки такое же, как у всех остальных ручек:

```json
{
  "timestamp": "2026-10-01T12:00:00",
  "status": "UNPROCESSABLE_CONTENT",
  "message": "Unprocessable content.",
  "errors": ["Unsupported format"]
}
```

| Код | Когда |
|---|---|
| `401` | нет токена или токен недействителен (оба эндпоинта) |
| `422` | формат не поддерживается, деталь `Unsupported format`: пустой файл, ZIP без расширения `.docx`, бинарный файл, не похожий на текст (`POST`) |
| `422` | старый или защищённый паролем документ Word либо RTF, деталь `Legacy format` (`POST`) |
| `500` | сбой записи файла на диск или сохранения в базу (`POST`), тело `Unexpected error occurred` |
